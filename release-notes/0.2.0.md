**What changed since v0.1.9**

- **The glibc Linux archives are renamed** `linux-x86_64-glibc` and `linux-aarch64-glibc`. In v0.1.9 they were bare `linux-x86_64` and `linux-aarch64`, which read as "the Linux build" and hid that they need the machine's glibc, libstdc++ and libgcc_s. Every Linux archive now says which kind it is: `-glibc`, or `-musl` (fully static, the one Homebrew on Linux installs). The binaries are built the same way as in v0.1.9; only the names changed. A script that downloads `csv2-<version>-linux-<arch>.tar.zst` has to add `-glibc` or `-musl`.
- `publish.zsh` refuses a Linux archive whose name ends in neither `-glibc` nor `-musl`, so a build that skipped `release.zsh`'s naming cannot be published under a bare name.
- **Windows** is still built with **Swift 6.4.2**: install the 6.4.2 runtime, as for v0.1.9.

**v0.1.9 之後的改變**

- **glibc 的 Linux 封存改名**為 `linux-x86_64-glibc` 與 `linux-aarch64-glibc`。v0.1.9 中它們是不帶字尾的 `linux-x86_64` 與 `linux-aarch64`，讀起來像「那個 Linux 版」，藏起了它們需要機器上的 glibc、libstdc++ 與 libgcc_s。現在每一份 Linux 封存都說出自己是哪一種：`-glibc`，或 `-musl`（完全靜態，Linux 上的 Homebrew 安裝的那一份）。執行檔的建置方式與 v0.1.9 相同，只有名稱改了。下載 `csv2-<version>-linux-<arch>.tar.zst` 的腳本要加上 `-glibc` 或 `-musl`。
- `publish.zsh` 拒收名稱既不以 `-glibc` 也不以 `-musl` 結尾的 Linux 封存，因此一份沒經過 `release.zsh` 命名的建置，無法以不帶字尾的名稱發布。
- **Windows** 仍以 **Swift 6.4.2** 建置：請安裝 6.4.2 的 runtime，與 v0.1.9 相同。
