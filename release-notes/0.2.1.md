**What changed since v0.2.0**

- **`-count` reads stdin.** `printf 'a,b\n1,2\n' | csv2 -count -si --headers 1` prints `1`. In v0.2.0 it refused a pipe with `-count needs -i FILE`, which sent callers checking "this pipe holds one record" to roundabout tests such as "`-get 2:1` must fail". On a pipe it always scans, since there is no index beside it. `--in-place` still refuses stdin: there is no file to write back to.
- **macOS 26 is the stated minimum.** The macOS binaries already declared 26.0, but only because the machine that built them ran 26; the build now fixes it, a test checks it, and the Homebrew formula declares it, so an older Mac is refused at install with the version named instead of getting a binary that will not start.
- **Windows** is still built with **Swift 6.4.2**: install the 6.4.2 runtime, as for v0.1.9 and v0.2.0.

**v0.2.0 之後的改變**

- **`-count` 可以讀 stdin。** `printf 'a,b\n1,2\n' | csv2 -count -si --headers 1` 印出 `1`。v0.2.0 會以 `-count needs -i FILE` 拒絕管線，逼得想確認「這條管線只有一筆紀錄」的呼叫端改用「`-get 2:1` 必須失敗」這類繞路的檢查。在管線上一律掃描，因為旁邊沒有索引。`--in-place` 仍然拒絕 stdin：沒有檔案可以寫回。
- **macOS 26 成為明文的最低版本。** macOS 執行檔原本就宣告 26.0，但只是因為建置它的機器跑 26；現在由建置固定、由測試檢查、並在 Homebrew formula 裡宣告，較舊的 Mac 在安裝時就會被拒絕並說出版本，而不是拿到一個啟動不了的執行檔。
- **Windows** 仍以 **Swift 6.4.2** 建置：請安裝 6.4.2 的 runtime，與 v0.1.9、v0.2.0 相同。
