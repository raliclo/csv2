**What changed since v0.1.8**

- **Linux archives are fully static**, linked against musl, and named `linux-x86_64-musl` and `linux-aarch64-musl`. They need no Swift toolchain and no glibc, so they run on any Linux of their architecture. v0.1.6 to v0.1.8 still needed the machine's glibc, libstdc++ and libgcc_s. Homebrew on Linux follows the new names.
- **Two new platforms**: `macos-x86_64` (Intel Macs) and `windows-arm64`. Six archives per release, each built, tested and packed on a machine of its own platform by `.github/workflows/release.yml`. Homebrew and Scoop do not list these two yet; download them from this page.
- **SP**: `-md` without `--pretty` no longer grows in memory with the input on macOS x86_64.
- **SO**: a SwiftPM package that depends on the CSV2Core subset needs `platforms: [.macOS(.v10_15)]` or higher; `plan/plan.md` phase 9 now says so.
- **Windows** is built with **Swift 6.4.2**: install the 6.4.2 runtime (it was 6.4.1 for v0.1.5 to v0.1.8).
- `./compile_csv2.zsh -musl` builds the static Linux binary from source; the default Linux build stays glibc.

**v0.1.8 之後的改變**

- **Linux 封存完全靜態**，對 musl 連結，命名為 `linux-x86_64-musl` 與 `linux-aarch64-musl`。不需要 Swift 工具鏈也不需要 glibc，因此在同架構的任何 Linux 上都能跑。v0.1.6 到 v0.1.8 仍需要機器上的 glibc、libstdc++ 與 libgcc_s。Linux 上的 Homebrew 會跟著新名字走。
- **兩個新平台**：`macos-x86_64`（Intel Mac）與 `windows-arm64`。每次發布六份封存，每一份都由 `.github/workflows/release.yml` 在它自己平台的機器上建置、測試並打包。Homebrew 與 Scoop 還沒有列出這兩個；請從這個頁面下載。
- **SP**：macOS x86_64 上，未加 `--pretty` 的 `-md` 不再隨輸入增加記憶體。
- **SO**：依賴 CSV2Core 子集的 SwiftPM package 需要 `platforms: [.macOS(.v10_15)]` 或更高；`plan/plan.md` 第 9 階段已寫明。
- **Windows** 以 **Swift 6.4.2** 建置：請安裝 6.4.2 的 runtime（v0.1.5 到 v0.1.8 是 6.4.1）。
- `./compile_csv2.zsh -musl` 從原始碼建出靜態的 Linux 執行檔；預設的 Linux 建置仍是 glibc。
