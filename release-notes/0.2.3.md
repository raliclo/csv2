**What changed since v0.2.2**

- **`-create` makes a file holding only its header rows (SX).** `csv2 -create 'user,hash' '使用者,雜湊' -o auth.csv2` writes the two header rows and no data, so the first row can then be added with `-append`. Each argument is one header row, written as one line of CSV text like `-append`'s ROW; the `-o` suffix decides how many (one for `.csv`, two for `.csv2`). It refuses an existing file (it never replaces one), an empty or repeated title, a title containing `:`, unequal field counts, and any flag beside it other than `-o`, `-log` and `-debug`. The new file is 0600, like every file `-o` creates. On Linux and macOS it needs a filesystem with hard links; on exFAT or FAT it fails rather than risk replacing a file another process just created. Before this, a header-only file could only be copied from a template (`csv2 -r -t --headers 2 -i T -o F`), which still works.
- **`-log` naming the `--value-file` is refused (SZ).** In v0.2.2 the log's first line was appended to the value file before it was read, so the cell received the value plus a log line, the value file was changed, and the run exited 0.
- **An unknown flag after `--version` or `--help` is now refused** instead of ignored: `csv2 --version -bogus` exits 1 (TA).
- **Windows** is built statically as in v0.2.2 and needs no Swift runtime.

**v0.2.2 之後的改變**

- **`-create` 建立一個只有標頭列的檔案（SX）。** `csv2 -create 'user,hash' '使用者,雜湊' -o auth.csv2` 寫出兩列標頭、沒有資料，之後就能用 `-append` 加上第一列。每個參數是一列標頭，寫法與 `-append` 的 ROW 相同，是一行 CSV 文字；`-o` 的副檔名決定要幾列（`.csv` 一列，`.csv2` 兩列）。以下情況會被拒絕：檔案已存在（絕不取代）、空的或重複的標題、含 `:` 的標題、欄數不等，以及 `-o`、`-log`、`-debug` 以外的任何旗標。新檔案是 0600，與 `-o` 建立的每個檔案相同。在 Linux 與 macOS 上需要支援硬連結的檔案系統；在 exFAT 或 FAT 上它會失敗，而不是冒險取代另一個行程剛建立的檔案。在這之前，只有標頭的檔案只能從範本複製（`csv2 -r -t --headers 2 -i T -o F`），那個方法仍然可用。
- **`-log` 指向 `--value-file` 會被拒絕（SZ）。** v0.2.2 會在讀取值檔之前先把 log 的第一行寫進去，於是那一格得到原值加一行 log、值檔被改掉，而且以 0 結束。
- **`--version` 或 `--help` 後面的未知旗標現在會被拒絕**，不再被忽略：`csv2 --version -bogus` 以 1 結束（TA）。
- **Windows** 與 v0.2.2 相同，是靜態建置，不需要 Swift runtime。
